# 01 — 像素风渲染选项：最近邻采样，绘制位置对齐物理像素

**What to build:** 游戏启动时打开一个像素风选项（暂定 `pixelArt: true`）后，所有贴图用最近邻采样，节点的绘制位置对齐到物理像素。
设备缩放不是整数时（例如 iPhone 横屏约 4.47 倍），像素图不模糊；节点慢速移动时不抖动、不出现半像素的边缘。
节点自己的 `position` 不变，只在绘制时取整，游戏逻辑和无头测试不受影响。

**Blocked by:** None — can start immediately

**Status:** done（2026-10-09）

- [x] 启动参数里的像素风开关，浏览器和小游戏的 `startGame` 都支持；默认关闭，现有游戏的行为不变
- [x] 开启后，所有贴图（包括图集的子区域和之后加载的贴图）都用最近邻采样
- [x] 开启后，绘制时节点的全局位置对齐到物理像素（考虑视口缩放和渲染分辨率），文字（Label）不受影响（对齐的是每个顶点，不是节点位置，见下方备注）
- [x] 渲染同步的测试覆盖：开关打开时采样方式和取整后的位置正确
- [x] 用一个现有示例在浏览器里对比开和关的效果
- [x] `llms.txt` 说明这个选项和适用场景

## Comments

**实现（2026-10-09）：** 启动参数 `pixelArt: true`（`GameOptions` 里，浏览器和小游戏的 `startGame` 都会传给渲染器；无头模式没有效果）。

- 采样：渲染器创建图片源时设 `scaleMode: 'nearest'`；图集的帧共用整张图的源，所以也是最近邻。文字的贴图按屏幕分辨率栅格化，仍是线性采样。
- 对齐：Sprite2D 的贴图层打开 Pixi 的 `roundPixels`，在顶点着色器里把每个顶点对齐到渲染目标的物理像素。只对贴图层打开（以后 TileMap 的区块 Mesh 也打开），
  文字、Graphics、视口遮罩不受影响。节点数据不变。
  和工单原文的差别：对齐的是每个顶点，不是节点的全局位置。代价（`llms.txt` 写明）：缩放倍数不是整数时，移动中的精灵宽度可能跳 1 个物理像素，
  旋转或缩放中的精灵形状会轻微抖动。按节点位置对齐要每帧算全局变换或自己写合批着色器，在 iOS 上太贵；改用整数倍缩放，见 09。
- 测试：`_createForSyncTests({ pixelArt })` 检查图片源（整张图和图集的帧）的采样方式，以及同步出来的精灵打开、文字没打开 `roundPixels`。
- 浏览器对比：在 sprite 示例里临时加了一张 16px 的像素图放大 6.5 倍，默认模式下模糊，打开后边缘清晰（临时改动已还原）。慢速移动时的抖动没有专门录屏验证，留给 08 在真机上检查。

**代码审查（2026-10-09）：** 原来对整个渲染器打开 `roundPixels`，会让文字和视口遮罩也对齐；改为只对贴图层打开，测试改为检查同步出来的 Pixi 对象。
图集帧边缘可能采到相邻帧的像素（最近邻 + 顶点对齐，UV 不变），估计在临界值附近，留给 08 在真机上检查；出现时按 ADR 0008 的做法把 UV 向内缩半个像素。
