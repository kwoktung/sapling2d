# 06 — 虚拟按键：屏幕上的触摸区域映射到输入动作

**What to build:** 小游戏没有键盘。游戏可以在屏幕上放按钮（左、右、跳），按住按钮时对应的动作处于按下状态（`isActionPressed('jump')`、`isActionJustPressed('jump')`），
和键盘绑定共用同一个动作名。支持多点触控（一只手按住“右”，另一只手按“跳”），手指滑出按钮或抬起时松开。

**Blocked by:** None — can start immediately

**Status:** done（2026-10-09）

- [x] 按钮按下 / 松开驱动动作状态，和键盘绑定同一个动作时两者都能触发
- [x] 多点触控：每个手指独立，同时按住两个按钮都生效
- [x] 手指滑出按钮、抬起、触摸取消、切到后台时，动作都会松开，不会卡住
- [x] 按钮的触摸区域可以比贴图大（手指比鼠标粗）
- [x] 浏览器里鼠标和触摸都能用；小游戏里触摸能用（浏览器鼠标用真实 PointerEvent 验证过；触摸和小游戏走同一条平台指针事件路径，没有在真机上点过）
- [x] 无头测试可以模拟多点按下和松开
- [x] 每帧不分配内存
- [x] `llms.txt` 加示例，说明和 `pointerPress()` 的区别

## Comments

**实现（2026-10-09）：**

- `TouchScreenButton`（名字照搬 Godot，继承 Sprite2D）：`action`、`texturePressed`、`passbyPress`（默认 false，和 Godot 一样）、`isPressed`、信号 `pressed` / `released`；触摸区域用 `hitArea`，没有就用贴图范围。
- Input 维护“哪个手指按着哪个按钮”，按钮被按住时给它的动作计数，动作状态 = 键盘绑定 || pointer 绑定 || 按钮计数 > 0。按在按钮上的手指不参与节点拾取，也不触发 `pointerPress()`。
- 松开：手指抬起 / 取消 / 滑出按钮；按钮离开树；游戏切到后台时 `Input._releaseAll()` 把按着的指针和按键排成 pointercancel / keyup（原来切后台时按着的键盘按键也会卡住，一起修了）。
- CanvasLayer 里的按钮按设计坐标判断；隐藏或不能处理（暂停）时按不下。未知的 `action` 在进入树时报错。
- 每帧不分配：只在指针事件时处理按钮，没有每帧的代码。
- 浏览器验证：用真实的 PointerEvent（鼠标）按下、滑出、在按钮外按下（临时 demo 已删除）。

**代码审查（2026-10-09）：** 修了：节点拾取和按钮共用一个命中判断 `hitsAt`（缩放为 0 的按钮原来全屏都能按到）；遍历按钮用副本（信号回调里增删按钮不会让别的按钮卡住）；
按钮按绘制顺序参与拾取（画在上面的对话框先收到指针）；滑进 passbyPress 按钮后不再算 `pointerPress()` 的按下，拖着节点的手指不按按钮；
切后台时队列里没处理的按下也取消；按着的按钮变得不能按（隐藏、暂停、等待销毁、被移除）时在下一帧开始统一松开，动作状态在 `_flush` 开头统一更新；
移动时用索引遍历和复用的数组，只检查按着的按钮和 passbyPress 按钮。未知动作改为警告（原来在进入树的过程中抛错，会让节点停在一半在树里的状态）。
