# Spec: examples/towerdefense（竖版塔防灰盒原型）

Status: ready-for-agent
Date: 2026-10-10

竖版塔防的灰盒原型：**用来验证头脑风暴里列出的引擎缺口是否真的需要**，不是做完整的游戏。和 platformer / spinblade 的做法不同：
这里遇到引擎不足时**先在游戏里绕过去**，记下绕的成本（代码量、性能、效果差多少），再决定哪些值得进引擎。结论写在本文“验证清单”和 01 的 Comments 里。

## 玩法（灰盒）

- 竖屏 750×1334、`expand`。怪物从屏幕上方出现，沿**随机曲线**往下走，走到底线扣一条命；命用完失败。
- 场地中间有一排排**英雄槽位**。底部是英雄栏（3 种英雄），点英雄再点空槽位就花金币放下一个英雄。击杀怪物得金币。
- 英雄自动攻击射程内**最靠近底线**的怪物；每种英雄的攻击不同：
  - 弓手：单体弹道（箭）；
  - 法师：火球，落地范围爆炸；
  - 剑士：近战扇形斩击，打中扇形里的所有怪物。
- 英雄有攻击序列帧（待机 2 帧、攻击 4 帧），用 01 的 `durations` 做前摇、出手、收招；**伤害在出手帧结算**。
- 一波怪全部消失（被杀或漏掉）后，从技能升级里**随机给 3 个选项，选 1 个**（伤害、攻速、射程、各英雄专属：多重箭、爆炸半径、斩击角度……）。升级对这一类英雄全体生效。
- 命中反馈：怪物受击变色、轻微击退、伤害飘字、火花粒子；击杀碎片；漏怪时屏幕震动。
- 美术是脚本生成的几何占位图（`scripts/gen-assets.mjs`）。

## 不做

- 局外养成、存档、音效、关卡选择、英雄出售/移动。
- 真实美术。真机性能测量单独一单（02），需要手机。

## 验证清单

每一项在原型里怎么绕、绕的成本如何（2026-10-10 填）。

| 缺口 | 原型里怎么用到 | 绕法和成本 | 结论 |
|---|---|---|---|
| **叠加混合（additive）** | 火球爆炸、刀光 | 没法绕：普通混合的光圈叠在怪物上是一团发灰的橙色，没有亮的中心（浏览器截图） | **进引擎，P0**。最便宜、效果差距最大 |
| **受击闪白** | 怪物受击 | 预生成白色剪影图 + 每只怪多一个子精灵。占位图上效果正确，代价是每只怪多一个精灵；换成帧动画的怪以后，每一帧都要一张剪影，图集翻倍 | **进引擎，P1**（真美术到位前做）：加色 / 闪白属性 |
| **Curve2D（样条 + 弧长）** | 怪物的随机曲线路径 | 游戏里写了 114 行（`src/path.ts`）。**踩了坑**：uniform Catmull-Rom 在随机控制点下约 5% 的路径出现尖角（相邻采样点的距离比掉到 0.08），换成 centripetal 才解决 | **进引擎，P1**。这类细节适合在引擎里做对一次 |
| UI 组件 | 三选一卡片、英雄栏 | `ColorRect` + `Label` 拼，约 120 行。**踩了坑**：`ColorRect` 不设 `inputPickable` 不能点，而且不报错；遮罩不设也不挡点击 | **文档先行**：llms.txt 写明 `ColorRect` 当按钮要 `inputPickable`。九宫格（NineSlice）等真美术到位再做 |
| BitmapText 飘字 | 每次命中一个数字 | Label 池 + 文字没变不重画。桌面 Chrome 6 倍降速：每秒 50 个**每次都不同**的数字，渲染平均只多 0.3 ms | **待真机（02）**。桌面数据不能代表 iOS 的文字栅格化 |
| Tween loop / yoyo | 选中按钮、卡片的呼吸 | 在 `process` 里用 `sin` 算，每处 4–6 行 | 不急：游戏里绕很便宜。顺手时补 |
| 范围查询 | 找目标、范围伤害 | 线性遍历。12 个英雄 × 60 只怪：逻辑 0.15 ms/帧（桌面），6 倍降速 0.52 ms | **不需要**（这个规模） |
| ySort | 怪物交叉 | 每帧 `zIndex = y`，一行 | 不需要专门的接口，文档里提一句即可 |
| 对象池 | 箭、飘字 | 手写，每种约 15 行（`active` 标记 + 找空闲） | 不需要进引擎 |
| 动作时间轴 / 帧事件 | 出手帧结算 | 01 的 `durations` + `frameChanged` 判断帧号，干净够用 | 不需要 |
| Line2D / Trail | 箭的拖尾 | 没做；箭很快，灰盒里看不出缺 | 暂不需要 |
| 粒子发射形状 / 旋转 | 火花、碎片、爆炸 | 点发射够用；爆炸环用放大淡出的光圈代替 | 暂不需要 |
| seeded noise | — | 路径用随机控制点 + 样条，不需要 | 不需要 |

性能（桌面 Chrome，移动端视口 400×712@2x）：12 个英雄 + 60 只怪 + 飘字，120 fps，逻辑 0.15 ms / 渲染 0.60 ms；CPU 6 倍降速时逻辑 0.52 ms / 渲染 3.67 ms（峰值 4.5 ms）。真机数据见 02。

**结论：** 进引擎的顺序是 additive → 闪白 → Curve2D；UI 先补文档。飘字等真机数据（02）再决定。其他几项在游戏里绕的成本很低，不进引擎。
