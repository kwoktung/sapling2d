# Spec: 微信小游戏资源分包 + 启动页

Status: ready-for-agent
Date: 2026-10-11

小游戏主包上限 4 MB。现在 `saplingWechat` 把 `public/assets` 整个拷进主包（`writeBundle`），hero-guard 资源 2.2 MB + 发布版 JS 约 0.9 MB，只能靠压图才放得下，美术再加一点就超。

分包之后，资源要在启动时下载，`Game.create` 现在先等入口场景的资源加载完才 `game.start()`，加载期间没有画面。所以分包和启动页一起做：**分包决定资源放在哪，启动页在下载 / 加载期间给出画面和进度**。

## 目标

- 启动页（浏览器和小游戏通用）：`startGame({ main, loading })`，`loading` 是一个普通场景，引擎先显示它，再准备资源包、加载 `main` 的资源、切到 `main`。
- `tree.loadProgress`（0..1，只读）：当前这次加载的进度；小游戏上分包下载和资源加载合并计算。`changeScene` 也更新它。
- 内置默认启动页：不传 `loading` 时用 `ColorRect` + `Label` 画背景和进度条，不需要任何资源。
- 小游戏构建：`public/assets/boot/`（可用 `mainAssets` 选项改）留在主包，其余进一个分包；构建时把主包文件清单内联进 `game.js`，`WechatPlatform` 按清单决定直接读还是先等分包。游戏代码的 `tex('xxx.png')` 不变。
- 发布构建检查包体：主包 / 分包 / 总包超限时构建失败，接近时警告并列出主包里最大的文件。开发构建只打印。
- 浏览器、`sapling()` 插件、开发流程不受影响。

## 不做

- 按场景拆成多个分包：等总包接近单个分包上限或首次加载太慢时再做（可以从场景的 `static assets` 推出分组）。
- CDN 远程资源（`wx.downloadFile` + 缓存）：需要合法域名和服务器，超过总包上限才值得。
- 切场景时自动显示加载页：先只在启动时用；`loadProgress` 已经有了，游戏可以自己做。
- 启动页的最短显示时间：由游戏自己决定（在启动页里等够时间再让引擎继续，见 02 的接口）。

## 已定

- 启动页就是 `Scene`，它的 `static assets` 只能用主包里的资源；用到分包里的资源时直接报错，指出文件和 `boot/` 目录（开发时在模拟器里第一次运行就能发现）。
- 启动资源用目录约定 `boot/`，`mainAssets` 选项可以改规则。浏览器里 `boot/` 只是普通目录。
- 分包只加载一次（缓存 Promise），由 `WechatPlatform` 负责，不暴露给游戏。
- 启动页的 `loaded()` 用来推迟切换（最短显示时间、点击继续），只在有帧循环时等它；`createTestGame` 默认不显示启动页（02）。
- 启动时准备资源包占进度的 70%，写死在 `Game.ts` 的 `PREPARE_SHARE`（02）。
- 生成的 `project.config.json` 关掉开发者工具的转译（`es6` / `enhance`）：否则 `game.js` 上传后变成 1.1–2.1 倍、无法预估（04）。
- 包体上限：主包 4 MB，单个分包不限，合计 30 MB（官方文档，01），写在插件里一处。所以只用一个资源分包，不按场景拆。
- 分包下载失败：重试 2 次，仍失败就报出清楚的错误（01 没测到真实的失败表现）。
- 读分包资源之前一律先等 `loadSubpackage`：新版本安装后能读到旧版本的分包文件（01）。

## 未定（Fog）

- 分包下载失败时启动页要不要显示错误、让玩家点击重试：等有真机的失败表现再定。
- 资源总量继续涨时，按场景分包还是上 CDN。
