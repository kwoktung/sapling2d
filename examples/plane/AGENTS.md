# Agent guide for this game

This is a [sapling2d](../../packages/engine/llms.txt) game: Godot-style node tree in TypeScript, PixiJS rendering, planck physics, running in the browser and as a WeChat Mini Game. **Read `node_modules/sapling2d/llms.txt` (or `packages/engine/llms.txt` in the sapling2d repo) before changing code** — it has the API, runnable examples and the common pitfalls.

## Layout

This is 飞机大战 (a vertical shoot-'em-up): drag to move, the fighter fires automatically.

- `src/game.ts` — `gameOptions` (entry scene, input actions) and the action / storage name registries.
- `src/config.ts` — all tuning numbers: player, weapon, enemy types, power-ups, spawn difficulty curve.
- `src/assets.ts` — every asset (one atlas for sprites, `sheet()` for explosions, sounds); all scenes share it.
- `src/scenes/` — `TitleScene` → `BattleScene` → `GameOverScene`. `BattleScene` owns input, firing, spawning and collisions, and exposes `spawnEnemy` / `spawnEnemyBullet` / `spawnPowerUp` for tests.
- `src/nodes/` — `Player`, `Enemy`, `Bullet`, `PowerUp`, `Background`, `Hud`, `PauseController`; `collision.ts` (`HitTester`, circle checks without the physics engine) and `bounds.ts` (visible area shared with bullets).
- `src/main.ts` — browser entry; `src/main.wechat.ts` — WeChat Mini Game entry. Keep both thin.
- `test/` — headless tests (Vitest + `createTestGame`). `battle.test.ts` uses `BattleScene` with `{ waves: false }` and places enemies itself.
- `public/assets/` + `src/sprites.json` — generated by `node scripts/gen-assets.mjs` (shapes drawn in code, sounds synthesized with ffmpeg). Change the script and re-run it instead of editing the PNGs.

Collisions are plain circle checks in `HitTester`, written for WeChat iOS (no JIT): positions are read into arrays once per frame and the inner loop only does arithmetic. Keep per-frame code free of allocations (see the performance section in llms.txt).

## Workflow

1. **Change behavior test-first.** Write or update a test in `test/` with `createTestGame`, then implement. Tests are deterministic: same `seed` + same inputs → same result.
2. **Run `pnpm check`** (= `tsc` + `vitest run`). Vitest does not type-check, so a green `pnpm test` alone is not enough.
3. **Look at the game state** without a browser: `console.log(g.dump())` prints the node tree (`Name (Type) prop=value`). Use it to understand failures before guessing.
4. **See it in a browser** with `pnpm dev` (Vite). In the page console, `sapling.tree.dump()` shows the live tree.
5. **WeChat:** `pnpm dev:wechat` writes `dist-wechat/`; open it in WeChat DevTools. Set `WX_APPID` (a test account works). For a phone, build with `SAPLING_RELEASE=1` and use DevTools' preview QR.
   - To read phone logs in the terminal: `pnpm log-server`, then build with `SAPLING_LOG_URL=http://<LAN IP>:7777/log` (the phone needs 开发调试 on). `snapshot('label')` from `sapling2d/wechat` saves a PNG of the phone screen under `logs/`.
   - The DevTools simulator differs from real phones; trust the phone.

## Writing tests

```ts
const g = await createTestGame({ ...gameOptions, seed: 1 })
g.tap(300, 400)        // design coordinates (750×1334 by default); advances 2 frames
g.stepSeconds(3)       // or g.step(frames); 60 frames per second
expect(g.tree.getNodesInGroup('balls')).toHaveLength(1)
expect(g.audio.log.map((s) => s.path)).toEqual(['pop.mp3']) // sounds are recorded, not played
```

- Arrange state directly through your scene's methods (e.g. `scene.spawn(v(x, y))`) instead of simulating long input sequences.
- Textures have size 0 in headless mode: give clickable sprites an explicit `hitArea`.
- `changeScene` completes in a microtask: `await` its result (or `await new Promise((r) => setTimeout(r, 0))`) before asserting.
- Pre-seed saves with `createTestGame({ storage: { best: 100 } })`.

## Rules of thumb

- `noUncheckedIndexedAccess` is on: `arr[i]` is `T | undefined`. Write `arr[i]!` when you know it exists.
- `g.dump()` lists each node's non-default properties (see the dump table in llms.txt). Override `protected dumpProps()` in your own nodes to expose game state you want to assert on.
- Positions are immutable `Vector2`: `node.x += 1`, never `node.position.x += 1`.
- Remove nodes with `queueFree()` (end of frame); guard with `isQueuedForDeletion` in collision callbacks — both bodies receive `bodyEntered`.
- Use `this.tree.rng`, not `Math.random`, so tests stay reproducible.
- Declare asset paths in a scene's `static assets` so they load before `ready()`; the Vite plugin fails the build on a missing file.
- Register group, action and storage names via `declare module 'sapling2d' { interface GroupRegistry {…} … }` to get type checking.
- Don't reach into Pixi (`unsafePixi`) unless the engine truly lacks the feature.
