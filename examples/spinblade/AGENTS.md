# Agent guide for this game

This is a [sapling2d](../../packages/engine/llms.txt) game. **Read `node_modules/sapling2d/llms.txt` (or `packages/engine/llms.txt` in the sapling2d repo) before changing code.**

## Layout

A top-down "spinning knives" brawler (like the WeChat mini game 转刀大闯关), portrait 750×1334. Spec and tickets: `.scratch/spinblade/` at the repo root.

- `src/game.ts` — `gameOptions` (entry scene, input actions: four directions + `confirm`) and the action name registry.
- `src/config.ts` — tuning numbers: fighter size and HP bars, player, enemy AI, Boss (spin swing, dash), ring, knife, hit feel (`FEEL`: hit-stop, shake, sparks, debris).
- `src/assets.ts` — every asset: the Tiled level (`tiledMap`) and textures.
- `src/scenes/Arena.ts` — the whole fight. Builds the arena from the Tiled map (tile layers `Floor` / `Walls` + `Entities` object layer: `Spawn`, `Enemy` (property `knives`), `Knife`, `Boss`). Its `physicsProcess` drives the step in order: every fighter's `step` → `KnifeCollider` (clashes knock knives off with sparks; body hits deal damage) → deaths (`kill`: the ring scatters, debris) → push-apart and ground-knife pickup with `HitTester`. Hit-stop (`tree.timeScale`) and screen shake (tween on `Camera2D.offset`) only when the player is involved. Flow: all enemies dead → `spawnBoss`; Boss dead → `Result` (cleared); player dead → `Result` (failed).
- `src/scenes/Result.ts` — cleared / failed screen; tap (`confirm`) to play again.
- `src/KnifeCollider.ts` — the game's own knife collision (rotated rectangles, swept with substeps so fast rings never pass through each other). Pure geometry, no engine imports. Deliberately not in the engine; see the header comment for when to move it.
- `src/nodes/Fighter.ts` — base class: a top-down `CharacterBody2D` (no gravity) blocked by wall tiles; owns a knife ring, `hp`, optional overhead HP bar (`ColorRect`).
- `src/nodes/Player.ts` — reads the joystick / WASD via `input.getAxis`.
- `src/nodes/Enemy.ts` — state machine (`chase` / `flee` / `collect` / `wander`), re-decides every 0.3 s; `passive = true` makes it stand still (tests).
- `src/nodes/Boss.ts` — Enemy that never flees, spin swings, dashes after a blinking warning strip.
- `src/nodes/Hud.ts` — `CanvasLayer`: player HP bar, knife count, enemies left, centre message, the `TouchJoystick`.
- `src/nodes/Knife.ts` — a knife: on the ground, flying (just knocked off), or in someone's ring (`owner`).
- `public/assets/` — generated by `node scripts/gen-assets.mjs`: flat placeholder shapes and the level as Tiled JSON (`levels/arena.json` + external tileset `levels/tiles.json`).
- `test/` — headless tests: `arena.test.ts` (movement, rings, pickup, push, clashes), `flow.test.ts` (enemy AI, hit feel, death, Boss, results, HUD), `KnifeCollider.test.ts` (against a brute-force reference).
- `bench/` — `pnpm bench` / `pnpm bench:jitless` (no JIT ≈ iOS): collider cost per step.

**All knives are direct children of the arena**, never of the spinning ring: each fighter places its ring knives every physics step (`placeKnives`) from the ring angle, so every knife lives in one coordinate system for hit testing and can drop to the ground or change owner without reparenting. Pushes go through `moveAndSlide` (as extra velocity), so a pushed fighter is still blocked by walls.

**Hit-stop ends via `timer.timeout.connect`, not `await`**: headless tests step many frames without yielding to microtasks, and an `await` would leave `timeScale` at 0. `Arena` resets `timeScale` to 1 on enter and exit.

## Workflow

Same as the other examples: test first with `createTestGame` (it reads the real level file from `public/assets`), `pnpm check`, `pnpm dev` for the browser (WASD / arrow keys, or drag on the left half of the screen, to move), `pnpm build:wechat` for the WeChat Mini Game. On WeChat the game logs `game.frameStats` every 5 seconds (`[perf] …`); build with `SAPLING_LOG_URL` and run `pnpm log-server` to read them.
